## 2026-02-02 - Component Extraction for Isolate Rendering
**Learning:** In shared React Native Web / Vite codebases, keeping complex nested state machines (like toggling help tooltips, managing clipboard transition states, and setting up native clipboard timeouts) colocated inside sub-components rather than the top-level App component drastically reduces parent rendering cascades. By wrapping sub-components in `React.memo` and hoisting global static variables (like `MOCK_TOKEN`) outside component scopes, rendering and virtual DOM reconciliation are avoided entirely when parent layout or polling status states change.
**Action:** Always identify localized state clusters and isolate them into dedicated `React.memo` functional components.

## 2026-02-03 - Primitive Prop Optimization for React.memo in Multi-lingual Apps
**Learning:** When using `React.memo` to prevent rendering cascades across component trees, passing dynamically resolved translation object references (like `t = translations[lang]`) can introduce subtle re-rendering triggers if the object gets recreated or reference is lost. Passing a primitive `lang` string prop (`"en" | "sw"`) and letting the memoized sub-component resolve its own translation reference from the global static translations dictionary ensures highly robust, O(1) primitive value comparison during React's shallow prop comparison checks, fully isolating components from re-rendering when unrelated sibling or parent states change.
**Action:** Pass primitive identifiers (like `lang` or `id`) rather than complex objects/dictionaries to `React.memo` components to guarantee referential stability and zero accidental render cascades.

## 2026-02-04 - Rollup Circular Chunk Avoidance during Code Splitting
**Learning:** When configuring custom Rollup manual chunks in a Vite web build using PNPM virtual store dependencies, grouping other external dependencies like Radix UI or Lucide into a single catch-all `vendor-others` bundle can introduce circular dependency cycles (e.g., `vendor-others -> vendor-react -> vendor-others`). This is because some other vendor modules import core React/React-DOM libraries. Isolating only extremely clean core vendor groups (such as `react-native-web` and `react`/`react-dom`) into dedicated chunks, and letting other miscellaneous modules bundle naturally, guarantees a clean build with zero circular warning logs.
**Action:** Define custom `manualChunks` with precise matching for stable leaf dependency libraries and avoid overly broad catch-all group mappings to prevent circular reference cycles across generated chunks.
